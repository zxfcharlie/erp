# 跨境电商 ERP 系统（MVP）

基于 FastAPI + SQLite 构建的轻量级 ERP 系统，Docker 默认端口 **8311**。

## 已实现功能

1. **用户注册/审核**
   - 任何人可在 `/register` 注册账号，注册后状态为"待审核"，需管理员在 `/admin/users` 审核通过后才能登录使用。
   - **系统第一个注册的账号会自动成为管理员并直接激活**，用于初始化系统。
2. **店铺与权限**
   - 管理员在 `/admin/shops` 创建/管理店铺。
   - 管理员在 `/admin/users` 为每个用户分配所属店铺（可多选）。
   - 普通用户登录后，`/orders` 订单列表 **只能看到自己所属店铺的订单**；管理员可看到全部并可按店铺筛选。
3. **物流商 API 配置（可扩展多个物流商）**
   - `/admin/logistics`：新增/启用/停用/设默认/删除 物流商配置。
   - 每条配置包含：类型（当前实现云途 YunExpress，预留"其他"占位方便后续扩展）、名称、**客户代码 / 密钥 / APPID**（对应您截图中的三个字段）、API 地址、备注。
   - 后续接入更多物流商时，只需：
     1. 在 `app/services/` 下新增一个 `xxx.py`，实现 `push_order(provider, order)` 函数；
     2. 在 `app/services/dispatcher.py` 的 `PROVIDER_MODULES` 字典里注册 `provider_type -> 模块`；
     3. 在物流商配置新增页面的下拉框里加一个选项。
     其余系统代码（订单表单、推送按钮等）无需改动。
4. **发货订单（手动创建 + 推送云途）**
   - `/orders/new`：目前表单**只保留必填字段**（所属店铺、订单金额/实收金额/采购成本、产品代码、申报币种、收件人信息、**发件人信息**、包裹信息、申报品名），销售平台/支付信息/税号/附加服务等选填字段暂未开放录入界面（数据库已支持，后续可以加编辑页面再补充）。注：发件人信息一开始按 Excel 示例行判断成了选填，实测云途接口要求 first_name/country_code/province/city/postal_code/phone_number 都必填，已改为必填。
   - 额外新增的业务字段：**所属店铺、订单金额、实收金额、采购成本(人民币)**，以及**创建时间、创建人**（这两项由系统在保存时自动记录，无需手填）。
   - 订单详情页可选择一个已启用的物流商配置，点击"推送生成运单"调用云途接口创建发货订单，成功后回填运单号/云途订单号。
5. **常用申报品名 + 产品代码搜索填充**
   - "申报品名"表格上方有"从常用品名中选择自动填充"下拉框；每行旁边有"保存为常用"按钮，保存后立即出现在下拉框里，下次新建订单可以直接选取自动填充整行（英文/中文品名、数量、FOB价、单重）。
   - "产品代码"输入框支持搜索自动填充：输入关键字会从后台"产品编码库"（`/admin/products`）里模糊匹配编码或名称并下拉提示，点击即可填入。
   - ✅ **云途"查询物流产品列表"接口已对接**：`GET /v1/basic-data/b2b/products/getlist`（鉴权方式与创建订单一致）。在"产品编码库"页面选择一个已启用的云途配置，点击"立即同步"即可把云途的产品编码/名称批量拉取并写入本地库，之后新建订单时的搜索框就能搜到。也可以继续用"单条新增"/"批量导入"手动维护。
6. **发件人信息按店铺保存预设，自动填充**
   - "发件人信息"区块右上角有"保存为该店铺默认发件人"按钮，填好后点一下即可把这份信息保存为**当前所选店铺**的默认发件人预设（同一个店铺一般发货地址都是固定的仓库/工厂地址）。
   - 下次新建订单，"所属店铺"下拉框选中该店铺后，如果之前保存过预设，发件人信息会**自动填充**；换成没保存过预设的店铺则保持空白等待手填。
   - 权限：管理员或该店铺的所属用户可以保存/更新对应店铺的发件人预设。
7. **外部系统推送订单接口**（供其他系统/脚本调用创建发货订单，**默认进入"待审核"状态**）
   - 接口：`POST /api/external/orders`
   - 鉴权：Header 里带 `X-API-Key: <店铺的外部推送API密钥>`（每个店铺一把，在 `/admin/shops` 页面查看/重新生成；已有店铺首次启动会自动补生成一把）。
   - 用这个 API Key 天然把订单归到对应店铺，不需要额外传用户/权限信息。
   - **只需要传业务信息**：客户订单号、订单金额、实收金额、采购成本、**商品名称**、收件人信息、发件人信息（这几项就是您截图里标红的内容，商品名称用作人工审核时填写"申报品名"的参考，是必填项）。**不需要**传产品代码、包裹重量/尺寸、申报品名这些物流细节——留空即可，这些交给人工审核时在 ERP 里补充。
   - 请求体 JSON 示例（最简版，只含必填内容）：
     ```json
     {
       "customer_order_number": "PO20260907001",
       "order_amount": 29.9,
       "actual_received_amount": 29.9,
       "purchase_cost_rmb": 60,
       "product_name": "木质拼图玩具",
       "receiver": {
         "country": "US", "name": "Carlos Answan", "house_number": "1066",
         "state": "MA", "zip": "02215", "address": "1066 Commonwealth Avenue",
         "city": "Boston", "phone": "6179877932"
       },
       "sender": {
         "name": "XD", "country": "CN", "state": "Guangdong",
         "city": "Zhongshan", "address": "xxx路xxx号", "zip": "528400", "phone": "13800000000"
       }
     }
     ```
     如果外部系统那边刚好也有产品代码/包裹/申报品名这些物流信息，也可以顺带传上（`product_code`、`declare_currency`、`package: {count, weight}`、`items: [{name_en, name_cn, qty, fob, unit_weight, ...}]`，格式同之前版本），传了会预填到订单里，人工审核时改起来更省事；不传就留空，等审核时人工补。
   - `sender` 字段可以不传：如果该店铺已经保存过"默认发件人预设"（见第6点），会自动用预设填充；两者都没有则返回 400 报错列出缺失字段。
   - curl 示例：
     ```bash
     curl -X POST https://你的域名或IP:8311/api/external/orders \
       -H "X-API-Key: 你的店铺API密钥" \
       -H "Content-Type: application/json" \
       -d '{...上面的JSON...}'
     ```
   - 成功返回 `201`：`{"success": true, "order_id": 1, "order_no": "SO...", "status": "draft", "review_status": "pending"}`；缺字段返回 `400` 并在 `missing_fields` 里列出具体缺了哪些（比如 `receiver.phone`）；API Key 无效返回 `401`。
   - **审核流程**：API 创建的订单固定是"待审核"状态，**在审核通过之前无法推送云途**（订单详情页"推送生成运单"按钮会被禁用）。ERP 里的人在"订单列表"能看到黄色"待审核"标签的订单（也可以用"审核状态"筛选框专门筛出来），点进详情页，先点"编辑/补充信息"补上产品代码、包裹重量、申报品名等物流字段，保存后回到详情页点"审核通过"，之后才能正常推送云途。手动在网页上创建的订单不受此限制，创建后直接是"已审核"状态（因为是员工自己填的，信息本身就是完整核对过的）。
8. **订单利润统计**（`/reports/profit`）
   - 基础利润 = 实收金额 − 采购成本(人民币)；最终利润 = 基础利润 − 实际物流运费。
   - 支持按**店铺**、**创建日期范围**筛选，页面顶部有合计卡片（订单金额/实收/采购成本/运费/基础利润/最终利润合计）。
   - 没有抓到运费数据的订单，最终利润显示"-"，不计入"最终利润合计"，避免拉低统计准确性。
9. **发货后自动/手动抓取实际运费、重量、签收状态**
   - ✅ 已对接云途"**获取运单扣费详情**"接口 `GET /v1/order/fee-details/get`：返回实际扣费合计(`total_amount`)、币种、计费重量/实际重量、费用明细(保险费/挂号费/清关费等)。
   - ✅ 已对接云途"**查询运单轨迹（全程，不受订阅限制）**"接口 `GET /v1/track-service/getAllForOPenApi`：轨迹事件里 `track_node_code == "DELIVERED"` 即视为已签收（官方示例已确认这个节点代码）。
   - 订单详情页（状态为"推送成功"时）会显示这两块数据，并有"**刷新物流状态**"按钮手动触发抓取；也提供了手动录入/修正实际运费的输入框，作为云途那边还查不到扣费数据时（通常要等结算后才有）的兜底方式。
   - **定时任务**：应用启动时会自动起一个后台定时任务（默认每 60 分钟一次，可用环境变量 `TRACKING_SYNC_MINUTES` 调整），自动扫描所有"推送成功但还未签收"的订单，批量刷新运费/轨迹，不用每单手动点。用的是 APScheduler 的 `BackgroundScheduler`，跑在同一个进程里，注意**如果以后改成多 worker 部署，这个定时任务会重复跑多份**，需要改造成分布式锁或换成外部 cron 调这个刷新逻辑。
10. **订单列表多字段筛选**
    - `/orders` 支持按**店铺、推送状态、签收状态、产品代码、客户订单号、运单号/跟踪号、创建日期范围**组合筛选。
11. **订单自动归档（控制主表体积，加快列表查询）**
    - `/orders` 主列表只保留最近 **200 条**（可用环境变量 `ORDER_ARCHIVE_KEEP` 调整），超出的老订单会被自动 **gzip 压缩**后存入历史归档表，并从主表删除。
    - 触发方式：① 应用启动时跑一次（处理存量数据）；② 后台定时任务默认每 **24 小时**跑一次（环境变量 `ORDER_ARCHIVE_CHECK_HOURS` 可调）；③ 管理员可以在订单列表页点"立即归档老订单"手动触发，不用等定时任务。
    - 历史订单在 `/order-archive` 页面查看，支持按店铺、关键字（内部单号/客户订单号/运单号）、日期范围搜索；点进详情会**实时解压**展示完整字段，压缩数据本身没有任何信息丢失。
    - 目前"利润统计"报表只统计主表里的在线订单，不包含已归档订单；如果需要跨归档数据做统计，后续可以再加一个专门遍历历史表的报表（会比较慢，量大的话建议做成异步任务）。


## 关于云途 OpenAPI 对接的说明

您提供的官方文档正文已经确认了完整的鉴权流程，系统已按此**真实实现**（不再是占位代码）：

1. **获取访问令牌**：`POST {base_url}/openapi/oauth2/token`，携带 `appId` / `appSecret` / `sourceKey` 换取 `accessToken`（有效期通常 7200 秒，当前实现是每次调用都重新获取一次，简单可靠；如未来订单量很大可以再优化为缓存令牌）。
2. **调用业务接口**：Headers 携带 `token`(accessToken)、`date`(毫秒时间戳)、`sign`。
3. **签名算法**：`sign = Base64( HMAC_SHA256( "body={请求体}&date={date}&method={method}&uri={uri}", secret=appSecret ) )`（无请求体时不含 `body=` 段）。
4. **创建订单接口**：`POST /v1/order/package/create`；正式环境 `https://openapi.yunexpress.cn`，沙箱环境 `https://openapi-sbx.yunexpress.cn`。请求体结构（`product_code`、`receiver`、`sender`、`packages`、`declaration_info`、`customs_number`、`extra_services`、`platform`、`payment` 等）已按文档字段实现，返回值 `{success, result:{waybill_number, tracking_number...}, msg, code}` 解析也已对接。

以上均已在 `app/services/yunexpress.py` 中实现，理论上可以直接联调。

**物流商配置表字段对应关系**（`/admin/logistics` 页面）：
- **APPID** → 云途 `appId`
- **密钥** → 云途 `appSecret`（既用于换取 accessToken，也用于计算签名）
- **sourceKey** → 云途"用户中心-用户信息"里的 sourceKey
- **客户代码** → 云途账号客户代码（部分场景/对账使用，当前下单接口暂未直接用到）
- **API地址** → 留空默认走正式环境，测试时可填沙箱地址 `https://openapi-sbx.yunexpress.cn`

**仍需要您协助确认/测试的点**：
- ✅ 附加服务代码表已按您提供的官方"附加服务表"实现：`20`偏远、`A0`单独报关、`G0`关税预付、`V1`代缴VAT、`10`出口退税、`VAS_IP`保价服务、`Ls0091`签名服务、`V4`云途预缴增值税号附加服务费。表单"附加服务"输入框可直接填写这些代码。
- 唯一不确定的是**保价服务(VAS_IP)金额的具体传值格式**：官方表格里 `extra_value` 给出的是 `EWFZ100001`(自定义保价保额)这个选项名，但没写清楚具体保价金额数字要怎么拼接进去。系统目前是猜测拼成 `"EWFZ100001:金额"`，建议先用沙箱环境实测一单确认格式是否正确。
- 建议先用**沙箱环境**跑通一单，把接口报错信息（订单详情页"查看接口返回原始数据"）发给我，方便对照错误码文档快速定位问题。


## 性能优化（适配小内存服务器，比如 AWS 上 8GB 内存的实例）

这套系统本身很轻量（FastAPI + SQLite 单文件数据库，单进程单 worker），8GB 内存跑起来完全没有压力，但顺手做了几个针对小内存/低配机器的优化：

1. **SQLite WAL 模式**：`app/database.py` 里给数据库连接设置了 `PRAGMA journal_mode=WAL`。系统里有后台定时任务(轨迹同步、订单归档)会和网页请求同时访问数据库，WAL 模式让读写可以并发进行，避免互相阻塞报 "database is locked"。同时设置了 `synchronous=NORMAL`（WAL下足够安全，比默认FULL少一些磁盘同步开销）、`busy_timeout=5000`（并发冲突时等待重试而不是直接报错）、`cache_size`给了约20MB（8GB内存完全负担得起，减少磁盘IO）、`temp_store=MEMORY`。
2. **订单自动归档**（见上方第11点）：主表只保留最近200条，避免订单量涨上去之后列表查询、索引都变慢/变大。
3. **响应 gzip 压缩**：`main.py` 里加了 `GZipMiddleware`，网页响应自动压缩，减少带宽占用，CPU开销很小。
4. **定时任务用单线程执行器**：APScheduler 配置了 `ThreadPoolExecutor(1)` + `max_instances=1` + `coalesce=True`，避免任务偶尔跑得比间隔久时被重复并发触发，额外占用内存。
5. **单 worker 部署**：`Dockerfile` 里 `uvicorn` 没有加 `--workers` 参数（默认单进程），这对 SQLite 场景是对的——SQLite 本来就不支持真正的多进程高并发写入，多开 worker 只会白白多吃内存，并不会提升性能。
6. **docker-compose.yml 加了内存上限** `mem_limit: 512m`：8GB的机器给这个单容器512MB完全够用，同时防止极端情况下(比如某次接口调用异常导致内存暴涨)拖累服务器上其它服务；如果以后功能变多觉得不够用，直接调大这个数字或删掉这行即可。

以上这些改动都不需要额外配置就生效；真要继续压榨性能，比较有价值的下一步是把 SQLite 换成 PostgreSQL（多进程/多worker水平扩展会更从容），但目前这个体量完全没必要。


## 快速开始（Docker）

```bash
cd erp
docker compose up -d --build
```

访问 `http://服务器IP:8311`，用第一个注册的账号登录（自动成为管理员）。

也可以直接用 Docker 构建运行：
```bash
docker build -t cross-border-erp .
docker run -d -p 8311:8311 -v erp_data:/data --name cross-border-erp cross-border-erp
```

数据库为 SQLite，数据文件保存在容器内 `/data/erp.db`（已通过 volume 持久化，容器重建不丢数据）。

## 目录结构

```
erp/
  app/
    main.py               # FastAPI 入口 + 定时任务(APScheduler)
    models.py             # 数据库模型（用户/店铺/物流商配置/订单/产品编码库/申报品名模板）
    database.py           # 数据库连接 + 自动补列迁移(auto_migrate)
    auth.py                # 登录鉴权
    routers/
      auth_router.py       # 登录/注册
      admin_router.py      # 用户审核、店铺管理、物流商配置、产品编码库、手动归档
      orders_router.py     # 订单列表(筛选)/创建/详情/推送/刷新物流状态
      reports_router.py    # 利润统计报表
      archive_router.py    # 历史归档订单查询
      api_router.py        # 内部JSON小接口(搜索/模板/预设) + 外部推送订单API
    services/
      yunexpress.py         # 云途适配器：下单/查询订单/费用详情/轨迹/产品列表
      dispatcher.py         # 物流商分发器（后续多物流商扩展点）
      sync.py                # 物流状态同步逻辑(手动按钮+定时任务共用)
      archive.py             # 订单归档压缩逻辑(手动按钮+定时任务共用)
    templates/              # 页面模板
    static/                 # 样式
  Dockerfile
  docker-compose.yml
  requirements.txt
```
